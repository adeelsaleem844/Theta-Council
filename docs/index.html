Most “AI trading agent” projects hand a language model an order endpoint and a prompt that says be careful. That is a nice demo and a bad trading desk.

Models are excellent at reading context across a dozen instruments at once, and unreliable about position size on the fortieth API call of the session. So this architecture inverts the usual arrangement.

The language model has a veto and a dial. It never has the wheel.

It can reject any trade and shrink any position. It cannot invent a strike, raise a quantity, widen a risk limit, or reach an order endpoint. Everything that could actually hurt the account is enforced afterwards, in deterministic Python, by an agent that does not read prompts.

The edge

Selling an option is selling a forecast of movement. The market prices that forecast at implied volatility; the underlying then delivers realised volatility. Across liquid US equity and index options the first is, on average, larger than the second. That gap — the variance risk premium — is not a directional prediction. It is a fee, paid to whoever is willing to carry the gamma risk.

# measured every cycle, per symbol vrp_ratio = ATM implied volatility ÷ 20-day realised volatility ≥ 1.12 the market overpays for movement → SELL defined-risk premium ≤ 0.98 movement is cheap → BUY defined-risk premium between → NO TRADE

That third branch is where a real desk spends most of its life, and it is the branch nobody demos. An agent that trades every time you run it is not finding edges, it is finding excuses.

Pricing the edge in dollars

“Vol looks high” is not a trade. Any vertical spread has a model value, so price it twice — once at the market's implied volatility, which is what we get paid, and once at the underlying's realised volatility, which is what we think it is worth.

# both legs, same measure, same horizon V_iv at market implied vol → what we get paid V_rv at 20-day realised vol → what we think it is worth spread we SELL: EV per share = credit − V_rv spread we BUY : EV per share = V_rv − debit edge_ratio = EV ÷ max_loss ← the ranking statistic

Because both legs are valued under the same measure over the same horizon, the difference is not a directional bet — it is the variance risk premium expressed in dollars. The credit is already haircut for the bid/ask we expect to cross, so the edge is quoted after friction rather than before it. If that number is not positive, the Architect never builds the structure, and the Risk Officer would block it if it did.

One cycle

  1. Intake
    One market brief, shared by every agent and journalled verbatim, so a decision is reproducible from the record.
  2. Read
    Analyst forms a regime view in ATR units, so SPY and NVDA are comparable. Vol Scout issues the sell / buy / stand-aside verdict.
  3. Manage — before entries, always
    Closing a winner returns risk budget and buying power that a new entry can then use. A desk that opens before it closes drifts to its position cap and sits there.
  4. Portfolio gates
    Kill switches, delta band, buying-power reserve, session clock. Any failure stands the whole desk down.
  5. Design
    Architect pulls real strikes from the live chain and prices its own EV after friction.
  6. Adjudicate
    The language model may veto and may shrink. Nothing else.
  7. Review
    Risk Officer gates each survivor and sets the size.
  8. Execute
    Single mleg orders, then journal everything — including the refusals.

What the model is actually for

Arithmetic cannot tell that three of today's candidates are the same index bet in three costumes, that a 1.4× premium across every megacap at once is a macro print being priced rather than five independent gifts, or that the book has quietly become one-way short puts. That is the model's entire job.

Its authority is deliberately tiny. It receives a closed list of already-validated structures. size_multiplier is clamped to ≤ 1.0, so there is no way to ask for more size. Invented candidate ids are dropped and logged. Silence is not consent — a candidate the model does not mention is discarded. If the call fails or returns unparseable output, the desk continues deterministically and the journal records that it did.

Refusals are decisions too

A desk that only logs its fills is grading its own homework. Blocked candidates are stored with the gate that stopped each one — from the same cycle:

One intent, three Alpaca pipes

The desk never calls Alpaca directly. It states an intent and a router uses the first transport that can serve it, recording which one did. That provenance table prints after every cycle and is stored per cycle — it is the evidence the CLI and MCP server are load-bearing here rather than decorative.

Alpaca CLI
preferred

JSON on stdout. Subcommands are probed with --help at startup rather than assumed, and the exact argv is journalled — so any decision can be replayed by hand in a terminal.

REST
guaranteed floor

Standard-library urllib. It exists so the desk never stalls because a binary is missing on someone else's machine.

Verified, not assumed

  • Spreads go over the CLI, not just REST. alpaca order submit takes --order-class mleg with a --legs JSON array. Its help notes --symbol and --side are “required for all order classes except for mleg” — for a spread they must be omitted, because they are per-leg. Getting that wrong is the difference between one spread and four naked options.
  • The dry run is the broker's, not ours. The CLI has its own --dry-run that validates and echoes the request body without submitting, so once --dry-run routes through it.
  • Discovery finds the tool; an alias table finds the parameter. The live MCP chain tool calls its underlying root_symbol, and close_position uses symbol_or_asset_id — neither is the obvious guess.
  • Credits are negative. Alpaca reports option credits as negative and debits as positive. Because that convention has shifted between releases, the first credit order is sent with the documented sign and, on a price rejection specifically, retried once with the sign flipped — then the answer is remembered and logged. It guesses once, out loud, and then stops.

Honest limitations

  • Realised volatility is a backward-looking forecast. A 20-day window is slow to see a regime change. The vol-shock gate and the 10-day/20-day ratio are the mitigations, and they are imperfect ones.
  • Earnings dates are operator-maintained. Alpaca serves no earnings calendar, so they live in a JSON file. Symbols absent from it are allowed with a note in the journal rather than silently blocked.
  • IV rank starts uninformative. It is a percentile of the desk's own observed history, so it needs days of cycles before it means anything. Until then it sits at 50 and contributes nothing.
  • The Bandit needs closed trades to say anything. Over a one-week competition its posterior stays close to the 0.5 prior by design — honest infrastructure for a longer run, not a claim to have learned the market in a week.
  • Fills are assumed at the haircut price. A limit that does not fill is not a loss, but it is not the trade the EV was computed for either.
